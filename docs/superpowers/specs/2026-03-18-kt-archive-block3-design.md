## 1. Цель и границы блока 3

**Цель блока 3:** добавить медиа‑модуль (изображения + видео) с локальным хранением, превью для изображений и постером для видео.  
**Не входит:** облачное хранение, транскодирование, HLS/стриминг, финальная дизайн‑полировка.

## 2. Ключевые решения

- **Хранение:** локально в `uploads/` с путями в БД.
- **Изображения:** `sharp` → превью 320px и 960px (webp).
- **Видео:** `ffmpeg` → постер‑кадр (jpg) + длительность.
- **Привязка:** медиа относится к патологии или протоколу (или обоим).
- **Доступ:** `GUEST` может только смотреть; загрузка/удаление запрещены.

## 3. Данные и структура хранения

### 3.1 Media модель
Добавить поля:
- `mimeType` (String)
- `width` / `height` (Int?, для изображений)
- `durationSec` (Float?, для видео)
- `previewSmall` (String?, путь к 320px webp)
- `previewLarge` (String?, путь к 960px webp)
- `poster` (String?, путь к jpg для видео)
- `protocolId` (String?, связь с Protocol)

### 3.2 Структура файлов
- Оригиналы: `uploads/original/{mediaId}.{ext}`
- Превью: `uploads/previews/{mediaId}_320.webp`, `uploads/previews/{mediaId}_960.webp`
- Постеры: `uploads/posters/{mediaId}.jpg`

## 4. Архитектура и API

### 4.1 API маршруты
- `POST /api/media` — multipart upload, обработка, запись в БД
- `GET /api/media?pathologyId=...&protocolId=...` — список медиа
- `DELETE /api/media/[id]` — удаление записи и файлов

### 4.2 Серверная обработка
- `lib/media/storage.ts` — пути, сохранение, удаление
- `lib/media/images.ts` — генерация превью (sharp)
- `lib/media/video.ts` — постер и длительность (ffmpeg)

### 4.3 Доступ
- `GUEST` запрещены POST/DELETE
- Сервер всегда проверяет роль

## 5. UI‑сценарии (минимальный UI)

- Блок **Медиа** на страницах патологии и протокола
- Список карточек (мини‑превью/постер + имя/тип)
- Кнопка “Загрузить” (скрыта для GUEST)
- Кнопка “Удалить” (ADMIN или автор)
- Видео отображается через `<video>` с постером, изображения через `<img>`

## 6. Ошибки

- `400` — неподдерживаемый тип файла
- `401/403` — стандартно по ролям
- `500` — общая ошибка

## 7. Тестовая стратегия

- Unit: генерация путей и проверка типов
- Integration: загрузка медиа + наличие записей
- Playwright (позже): загрузка и просмотр
