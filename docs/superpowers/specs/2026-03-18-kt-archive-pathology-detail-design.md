# КТ-Архив — страница патологии и медиа‑исправления

Дата: 2026-03-18

## 1. Цель и границы

**Цель:** сделать кликабельные карточки патологий с переходом на отдельную страницу патологии, и устранить проблемы с отображением/удалением медиа.  
**Не входит:** расширенный rich‑text рендер, масштабный редизайн карточек, миграции БД.

## 2. UX и навигация

- Клик по карточке патологии в разделе ведет на `/pathologies/[id]`.
- На странице патологии доступны:
  - Заголовок.
  - Текстовое описание (fallback на `contentText`).
  - Блоки: Медиа, TODO, Комментарии.
  - Кнопка «Назад в раздел» (по `categoryId`).

## 3. Страница патологии

### 3.1 Маршрут
- Новый маршрут: `/pathologies/[id]`.

### 3.2 Данные
- Запрос на `GET /api/pathologies/[id]`, включая `categoryId`, `contentText`, `contentJson`.
- Если `contentJson` есть, пока показываем `contentText` (минимальный рендер без TipTap‑вывода).

### 3.3 Состояния
- Заглушка/скелетон при загрузке.
- Сообщение «Патология не найдена» при `null`.

## 4. Карточки в списке

- Карточка становится ссылкой на `/pathologies/[id]`.
- В карточке остаются только краткие данные (заголовок), без описания.

## 5. Медиа: надежная отдача и действия

### 5.1 Отдача файлов
- В `GET /api/media/file/[id]`:
  - Если запрошенный `variant` отсутствует, отдавать `original` вместо 404 (fallback для изображений).

### 5.2 UI‑поведение
- В `MediaGallery`:
  - Обрабатывать ошибки загрузки медиа (показывать текстовую ошибку).
  - При ошибке превью — пытаться показать оригинал.
  - Кнопку «Удалить» блокировать на время запроса.

### 5.3 Мутации
- В `useUploadMedia`/`useDeleteMedia`: проверять `res.ok`, иначе бросать ошибку для UI.

## 6. Ошибки и безопасность

- Все медиа‑роуты требуют авторизацию.
- Ошибки от API выводятся пользователю в виде короткого сообщения в блоке медиа.

## 7. Тесты (минимум)

- Unit: проверить fallback‑логику для `variant`.
- Интеграционные: загрузка изображения + удаление.

## 8. Риски

- Риск: отсутствие визуального rich‑text рендера на странице патологии.  
  **Компенсация:** пока показываем `contentText`, полноценный рендер вынести в отдельный блок.
